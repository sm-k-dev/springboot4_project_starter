# 할 일 CLI 출력 문구·형식 (최종안)

작성: 수아 (디자이너) · 기준: `docs/design.md` 4장 · 대상: 민준(검토), 서연(구현·테스트), 태양(리뷰)

이 문서의 문구가 `docs/design.md` 4장의 기본 문구와 다르면, 해당 항목에 **[변경]** 표시와 이유를 적었습니다. 표시가 없는 문구는 4장 그대로입니다.

## 1. 공통 원칙

- **성공·안내 메시지는 stdout, 오류 메시지는 stderr** 로 출력합니다.
- 오류 메시지 첫 줄은 `오류: <설명>` 형식을 따릅니다. 두 번째 줄은 필요한 경우에만 `힌트:` 또는 안내 문장으로 씁니다.
- 한 항목은 한 줄로 출력합니다. 내용의 줄바꿈(`\n`, `\r`, `\t`)은 공백 하나로 바꿔 저장·출력합니다. (민준 채택, design.md '출력 문구의 기준 문서' 절)
- 종료 코드는 4장과 같습니다. `0` 성공, `1` 실행 오류, `2` 사용법 오류.

## 2. 명령별 성공 문구

| 명령 | 상황 | 출력 (stdout) | 종료 코드 | 비고 |
|---|---|---|---|---|
| `todo add <내용...>` | 추가 성공 | `추가됨: #3 우유 사기` | 0 | 4장과 동일 |
| `todo done <id>` | 완료 처리 성공 | `완료: #3 우유 사기` | 0 | 4장과 동일 |
| `todo done <id>` | 이미 완료된 항목 | `이미 완료된 항목입니다: #2 보고서 제출` | 0 | 4장과 동일. 오류가 아니므로 stdout |
| `todo list` | 항목이 있음 | 아래 3장 형식 | 0 | 4장과 동일 |
| `todo list` | 항목이 없음 | `할 일이 없습니다. \`todo add <내용>\`으로 추가해 보세요.` | 0 | **[변경]** 아래 4장 참고 |

## 3. `list` 출력 형식

```
#1 [ ] 우유 사기
#2 [x] 보고서 제출
#10 [ ] 세탁물 맡기기
```

- 한 줄에 `#<id> [상태] <내용>` 입니다. 상태는 미완료 `[ ]`, 완료 `[x]` 두 가지뿐입니다.
- id는 오름차순입니다. 완료 항목도 항상 표시합니다.
- **[변경]** id 뒤에 공백을 넣어 상태 표시 위치를 맞춥니다. 가장 큰 id의 자릿수(w)만큼 id 칸을 맞추고(왼쪽 정렬), 그 뒤에 공백 한 칸과 상태를 붙입니다. 예를 들어 id가 1~9뿐이면 `#1 [ ]`, id 10이 있으면 `#1  [ ]`처럼 됩니다.
  - 이유: 4장 예시는 id가 한 자리일 때만 맞습니다. 10번 이후부터 열이 밀려 보이므로, 자릿수에 맞춰 상태 열을 고정합니다.
  - 구현 힌트(서연): `f"#{task.id:<{w}} [{'x' if task.done else ' '}] {task.title}"`, 여기서 `w = len(str(max(id)))`.

## 4. 빈 목록 문구

- **[변경]** 최종 문구: `할 일이 없습니다. \`todo add <내용>\`으로 추가해 보세요.`
- 4장 기본 문구는 `할 일이 없습니다.` 입니다.
- 이유: 처음 쓰는 사람이 목록이 비었을 때 다음에 무엇을 해야 할지 바로 알 수 있게 하기 위함입니다. 명령 예시가 한 줄 붙는 것뿐이라 화면은 그대로 짧게 유지됩니다.
- 빈 목록은 실패가 아니므로 종료 코드는 `0`, 출력은 stdout입니다.

## 5. 오류 문구

| 상황 | 출력 (stderr) | 종료 코드 | 비고 |
|---|---|---|---|
| `add`에 빈 내용 (앞뒤 공백 제거 후 빈 값) | `오류: 할 일 내용이 비어 있습니다.` | 1 | 4장과 동일 |
| `done`에 없는 id | `오류: #9 항목을 찾을 수 없습니다.`<br>`힌트: \`todo list\`로 id를 확인하세요.` | 1 | **[변경]** 2번째 줄 추가 |
| 저장 파일을 읽을 수 없음(손상·구조 오류) | `오류: 할 일 파일을 읽을 수 없습니다: <경로>`<br>`파일은 수정하지 않았습니다. 내용을 확인하거나 백업해 두세요.` | 1 | **[변경]** 2번째 줄 추가 |
| 저장 실패(권한 등) | `오류: 할 일 파일을 저장할 수 없습니다: <경로>`<br>`변경 내용은 저장되지 않았습니다. 파일 권한을 확인하세요.` | 1 | **[변경]** 2번째 줄 추가 |
| `done`의 id가 숫자가 아님 | `todo done: error: argument id: id는 숫자여야 합니다 (예: todo done 3)` | 2 | **[변경]** 아래 5.1 참고 |
| `add`에 내용 없이 실행 (`todo add`만 입력) | `오류: 할 일 내용이 비어 있습니다.` | 1 | 4장과 동일. 빈 내용 오류로 통일 (민준 결정) |

### 5.1 `done` id 숫자 오류를 한국어로 바꾸는 이유

- argparse 기본 문구(`invalid int value`)는 영어입니다. 나머지 문구가 모두 한국어이므로 어색합니다. 민준 채택.
- 서연 구현 방법: `done`의 id 타입은 `type=` 함수로 받아 실패 시 `argparse.ArgumentTypeError("id는 숫자여야 합니다 (예: todo done 3)")`를 던집니다.
- argparse의 `usage:` 줄은 유지합니다. 사용법 줄을 지우면 사용자가 정확한 사용법을 못 보게 되기 때문입니다.
- `todo add`를 인자 없이 실행한 경우는 종료 코드 2 대신 빈 내용 오류(종료 코드 1)로 처리합니다. 민준 결정에 따라 이 안은 채택하지 않았습니다.

## 6. 4장 기본 문구에서 바뀐 항목 요약

| 항목 | 기본 문구 (4장) | 최종안 | 이유 |
|---|---|---|---|
| 빈 목록 | `할 일이 없습니다.` | `할 일이 없습니다. \`todo add <내용>\`으로 추가해 보세요.` | 다음 행동 안내 |
| list 열 정렬 | `#1 [ ] 우유 사기` | id 자릿수에 맞춰 상태 열 정렬 | id 10 이후 열 어긋남 방지 |
| 없는 id | 1줄 | 2줄 (`힌트:` 추가) | 복구 방법 안내 |
| 파일 손상 | 1줄 | 2줄 (데이터 미수정 안내) | 사용자가 데이터 안전을 확인할 수 있게 함 |
| 저장 실패 | 1줄 | 2줄 (변경 미저장 안내) | 추가·완료가 반영되지 않았음을 명확히 함 |
| id 숫자 아님 | argparse 영문 기본 문구 | 한국어 문구 | 문구 언어 통일 |

나머지 성공 문구(`추가됨`, `완료`, `이미 완료된 항목입니다`)와 빈 내용 오류는 4장 그대로입니다.

## 7. 서연 구현·테스트 체크리스트

- `test_cli.py`에서 아래 문자열을 **정확히** 비교합니다(stdout/stderr 분리).
  - `추가됨: #1 우유 사기`
  - `완료: #1 우유 사기`
  - `이미 완료된 항목입니다: #1 우유 사기`
  - `할 일이 없습니다. \`todo add <내용>\`으로 추가해 보세요.`
  - `오류: #9 항목을 찾을 수 없습니다.` 다음 줄에 `힌트: \`todo list\`로 id를 확인하세요.`
  - `오류: 할 일 내용이 비어 있습니다.`
- `list` 정렬: id 1~9만 있을 때와 id 10을 포함할 때 각각 상태 열 위치가 같은지 확인합니다.
- `todo add`(인자 없음)와 `todo add "  "`(공백만)는 모두 `오류: 할 일 내용이 비어 있습니다.`를 종료 코드 1로 출력하는지 확인합니다.
- `done`에 숫자가 아닌 id를 넣으면 한국어 문구와 종료 코드 2를 확인합니다.
- 종료 코드 0/1/2를 모두 확인합니다.
- 문구는 이 문서가 기준입니다. 4장과 이 문서가 다르면 이 문서를 따릅니다(design.md 7장 규칙과 일치).

## 8. 민준 검토 결과 (반영 완료)

- 채택: `list` 자릿수 정렬(3장), `done` id 숫자 오류 한국어화(5.1), 줄바꿈→공백(1장).
- 불채택: `todo add` 인자 없음의 종료 코드 2 안. 빈 내용 오류(종료 코드 1)로 통일합니다(5장 표).
